# Unity 客户端 Protobuf / WebSocket 协议说明

本文档说明 Unity 客户端 `g1Client` 与 Gate 的当前二进制协议实现、代码生成方式和维护约定。

## 1. 协议边界与目录

| 范围 | 权威协议源 | 是否生成到 Unity |
| --- | --- | --- |
| 客户端 ↔ Gate / Game 业务消息 | `../protocol/cspb/**/*.proto` | 是 |
| Gate / Game / 服务间内部消息 | `../protocol/sspb/**/*.proto` | 否 |
| Platform gRPC 消息 | `../protocol/pfpb/**/*.proto` | 否 |

协议源以根目录 `protocol` 为准。**不要直接编辑**以下生成文件：

- Unity：`Assets/Scripts/Proto/Generated/*.cs`
- 服务端：`gogs/pb/**/*.pb.go`、`gogs/pb/register.go`

例如，`event` 已属于 `sspb` 服务端内部协议，因此不会生成到 Unity。

## 2. 连接与帧格式

客户端默认连接 Gate：

```text
ws://127.0.0.1:8081/ws
```

传输层实现为 `Assets/Scripts/Network/NativeWebSocketTransport.cs`，使用 NativeWebSocket 并在握手时声明 WebSocket 子协议：

```text
protobuf
```

Gate 在 `gogs/gate/ws/server.go` 中根据该子协议选择 `codec.ProtoCodec`。一个 WebSocket 二进制消息就是一条完整协议帧：

```text
| 2 bytes msgID (big-endian) | protobuf message body |
```

客户端帧编解码见 `Assets/Scripts/Network/FrameCodec.cs`；服务端对应 `tree/codec/proto.go`。这不是 Gate ↔ Game 的 `pb_gateway.Frame`：后者仅在 Gate 内部转发时包装客户端原始 payload。

## 3. 消息 ID

消息 ID 不是 proto 字段，也不是手工递增值。两端都按以下规则计算：

```text
msgID = uint16(FNV-1a(GoPackagePath + "." + MessageName))
```

示例：

```text
FNV-1a("github.com/gogu-x/gogs/pb/cspb/pb_gateway.GetServerListReq")
```

取低 16 位后，以大端写入帧头。当前 `GetServerListReq` 的 ID 为 `0x4AE7`。

客户端映射表位于 `Assets/Scripts/Network/MsgIdRegistry.cs`。新增、删除、移动消息或修改 `.proto` 的 `option go_package` 后，必须同步该映射；否则 Gate 会因为未知 msgID 丢弃请求，客户端表现为超时无响应。

> 映射中的包路径必须是当前 `go_package` 的完整值，例如 `github.com/gogu-x/gogs/pb/cspb/pb_gateway`，不能使用旧的 `pb/protoGateway` 路径。

## 4. Protobuf 生成

### 4.1 Unity 客户端

在 `g1Client` 目录执行：

```bat
python tools\gen-proto-csharp.py
```

脚本：`tools/gen-proto-csharp.py`

输出：`Assets/Scripts/Proto/Generated`

该脚本有三项职责：

1. 仅扫描 `../protocol/cspb`；`sspb` 和 `pfpb` 不属于 Unity 网络消息。
2. 在临时副本中把同名的 `req.proto`、`ack.proto`、`struct.proto` 改为唯一文件名并同步 import，避免 `protoc` 生成同名 C# 文件/反射类冲突。
3. 对每个顶层 `*Req` 应用与 Go 生成器相同的公共头注入和字段重编号规则。

生成脚本会清理此前由 `protoc` 生成的 C# 文件，再重新生成。手写的网络层、UI 代码不会被清理。

### 4.2 Go 服务端

在 `gogs` 目录执行：

```bat
make proto
make register
```

其中 `tools/gen-proto.py` 生成 Go PB，`tools/gen-register.py` 生成 `pb/register.go`，将 `Req`、`Ack`、`Ntf` 等消息注册到 `codec.ProtoCodec`。

## 5. 请求公共头与字段号

共享 `.proto` 中的请求业务字段从便于阅读的编号开始定义；生成时，所有顶层 `*Req` 都会先注入：

```proto
uint64 uID       = 1;
uint32 serverID  = 2;
string sessionID = 3;
```

随后业务字段从 `4` 起顺延。例如源定义：

```proto
message GetServerListReq {
  string account = 1;
}
```

Unity 和 Go 的**生成结果**均是：

```proto
message GetServerListReq {
  uint64 uID       = 1;
  uint32 serverID  = 2;
  string sessionID = 3;
  string account   = 4;
}
```

因此客户端必须使用当前生成的 `GetServerListReq`，不能手写 `account = 1` 的二进制编码。

客户端构造请求时通常只填业务字段；Gate 在登录后将请求转发给 Game 前，会通过 `codec.WriteHeader` 覆盖 `uID`、`serverID`、`sessionID`，不能信任客户端传入的身份字段。

## 6. 客户端收发 API

业务代码应使用 `NetworkManagerExtensions` 的类型安全封装，而非直接传递字节数组。

发送：

```csharp
NetworkManager.Instance.SendProto(new global::GetServerListReq
{
    Account = account,
});
```

接收：

```csharp
NetworkManager.Instance.RegisterProtoHandler(
    "ServerListAck",
    global::ServerListAck.Parser,
    OnServerListAck);
```

`SendProto` 自动通过 `IMessage.Descriptor.Name` 获取消息名、调用 `ToByteArray()`，再经 `FrameCodec` 加上 msgID。`RegisterProtoHandler` 自动按对应 `MessageParser<T>` 反序列化回包。

直接使用 `NetworkManager.Send(string, byte[])` / `RegisterHandler(string, Action<byte[]>)` 仅适用于协议基础设施；业务层应优先使用上述类型安全 API。

## 7. 当前登录与选服流程

`Assets/Scripts/UI/HomePanel.cs` 的启动链路如下：

```text
Connect WebSocket
  → GetServerListReq { account }
  → Gate.onGetServerList
  → Platform.GetServerList
  → ServerListAck { code, accounts }
  → 若无角色：展示可注册区服
  → RegisterReq / RegisterAck（如需要）
  → LoginReq / LoginAck
```

Gate 在 `gogs/gate/conn/router.go` 中直接路由以下匿名阶段消息：

- `LoginReq`
- `RegisterReq`
- `GetServerListReq`

登录完成后，普通客户端消息由 Gate 写入公共请求头并转发 Game。当前 `ServerListAck` 的字段为：`code = 1`、`accounts = 2`；应直接使用生成的 `ServerListAck.Parser`，不要再使用旧的手写选服解析器。

## 8. 新增或修改 cspb 消息的流程

1. 修改 `protocol/cspb/<module>/*.proto`。
   - 尽量只新增字段；已发布字段不可改类型或复用字段号。
   - 新增 `*Req` 的业务字段在源文件按自然顺序写；生成器会统一变为字段号 `4+`。
2. 在 `gogs` 执行：

   ```bat
   make proto
   make register
   ```

3. 在 `g1Client` 执行：

   ```bat
   python tools\gen-proto-csharp.py
   ```

4. 更新 `Assets/Scripts/Network/MsgIdRegistry.cs`。
   - 为能经 WebSocket 收发的每个消息登记 `消息名 → 当前 go_package`。
   - 同名消息必须避免跨包歧义。
5. 补充服务端路由/处理。
   - Gate 直接处理的消息：在 `gogs/gate/conn` 注册路由和业务处理。
   - 登录后转发给 Game 的消息：确认 Game 已注册该 PB 类型并有处理逻辑。
6. 在客户端通过 `SendProto`、`RegisterProtoHandler` 接入 UI/业务逻辑。

## 9. 验证清单

协议变更后至少执行：

```bat
:: g1Client
python tools\gen-proto-csharp.py

:: gogs
make proto
make register
go test ./pb ./gate/conn
```

并在 Unity 中验证：

- 生成 C# 无编译错误；
- WebSocket 已协商 `protobuf` 子协议；
- 发送日志中的消息名正确；
- Gate 未出现 `unknown msgID` 或 protobuf 字段 wire type 错误；
- 对应 Ack/Ntf 能由注册的 `MessageParser<T>` 正确解析。

## 10. 常见故障

| 现象 | 常见原因 | 检查位置 |
| --- | --- | --- |
| 请求超时、Gate 无业务日志 | `MsgIdRegistry` 使用旧 `go_package`，msgID 不一致 | `MsgIdRegistry.cs`、`.proto` 的 `go_package` |
| Gate 报 protobuf wire type 错误 | 客户端未按当前生成的 `*Req` 字段号发送 | 重新执行客户端 PB 生成，禁止手写业务 payload |
| 收到回包但客户端解析失败 | 仍使用过期手写解析器或未注册 parser | `HomePanel.cs`、`RegisterProtoHandler` |
| `FrameCodec` 报消息未登记 | 新消息未加入 `MsgIdRegistry` | `MsgIdRegistry.cs` |
| Unity 生成类重名或输出冲突 | 直接对共享目录一次性 `protoc --csharp_out` | 使用 `tools/gen-proto-csharp.py` |
